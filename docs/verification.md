# 脚本差分验证

差分验证器在隔离宿主中分别执行原脚本和转换后的 Egern 脚本，比较完成结果、HTTP 请求、存储写入顺序、最终存储和通知。构建验证由维护者显式开启；日常构建默认只做静态分析。

```sh
# 构建时对所有成功编译的脚本运行差分验证
.venv/bin/python build.py --offline --verify
# 发布可用内容，同时排除验证失败脚本及依赖模块（Actions 使用此模式）
.venv/bin/python build.py --offline --verify --isolate-script-failures
# 检查已有站点产物
.venv/bin/python -m tools.egern_hub.verify
# 要求每个脚本都触发可观测行为
.venv/bin/python -m tools.egern_hub.verify --require-covered
```

验证输入由模块规则和原脚本 AST 自动生成。分析器提取 JSON 字段访问、数组回调、函数参数、属性存在判断、嵌套 JSON 和替换正则等静态事实，并尝试 URL、路径、查询、正则文本及 HTML 分支。探针是确定性的合成输入，不访问真实网络，也不依赖仓库内人工维护的 JSON 数据。

每个脚本最多生成 48 个基础输入，并考虑最多 8 个模块上下文；4 个工作线程并行执行。正则无法构造或模块上下文缺失时仍尝试基础输入，但输入没有触发实际行为时不会记作功能通过。设备分类参数按脚本声明生成 iPhone、iPad 和 Mac 三组参数场景。

探针缺少 HTTP 响应时，验证器最多从原脚本收集两个输入、每个输入最多四个请求，并使用生成的 JSON 作为合成响应，再从头执行原脚本和转换脚本。该回放只检查这组合成输入下的调用和处理一致，不表示线上接口可用或覆盖了其他响应结构。

除两侧观测一致外，验证器还检查原脚本是否改变消息、直接响应或中止，或产生 HTTP、存储、通知事件。仅重新序列化相同 JSON 不算触发实际行为。自动输入导致的原文错误、模拟响应不足和未匹配分支都会保留原因，不会因为两侧都没有结果而算通过。

## 报告状态

| 状态 | 含义 |
| --- | --- |
| `probe_passed` | 自动输入一致，且至少一次在匹配入口触发实际行为 |
| `partial` | 已触发行为且结果一致，但其他输入仍有原文错误或模拟输入不足 |
| `baseline_only` | 执行结果一致，但没有在匹配入口触发可观测行为 |
| `inconclusive` | 已尝试执行，但输入不足以确认转换行为 |
| `not_covered` | 没有可执行输入，未进行动态验证 |
| `failed` | 检出两侧差异、转换侧错误或独立预期不符 |

脚本报告记录 `coverage.attempted`、`completed`、`effective` 和 `complete_branch_coverage`。`complete_branch_coverage` 始终为 `false`；自动探针不是全输入等价证明，也不是 Egern 真机测试。`--require-covered` 只接受 `probe_passed`，其他状态返回非零。

原生模块正文保持原样，不纳入转换脚本差分验证。JavaScript 和 Python 正则语法不完全相同，候选 URL 与字段值只是探针，不代表真实流量分布。真实接口结构、线上状态、设备运行时和异步时序仍可能超出模拟宿主覆盖；报告不得表述成“全部功能验证通过”。

Actions 的网站门禁与转换器回归分开。转换失败或差分状态为 `failed` 的脚本及依赖它的整个模块不进入站点，其他资源可继续发布；失败记录仍保留，不能算作验证通过。没有定位到具体脚本的验证器异常、网站检查失败与发布错误仍会停止发布。转换器回归在网站发布后独立运行，失败会出现在日志和步骤结果中，不阻止已通过网站检查的内容上线。默认 `--verify` 的严格模式保持不变。

验证宿主分别运行原脚本与转换脚本，不导入转换器实现，也不依赖 Script-Hub 或 NSNanoCat/util。每个执行使用独立 VM 上下文；禁用外部导入和 WebAssembly，不注入宿主可调用对象，不传递环境密钥，也不访问真实 HTTP、存储或通知。单次 VM 执行超时 500ms，子进程超时 5 秒，堆限制 128 MiB。
