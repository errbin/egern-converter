# 平台转换与可验证边界

所有资源按“源头原文 → 声明解析 → Egern 配置 / 原生脚本 → 语法检查与差分验证”构建，不运行上游转换服务，也不依赖 Script-Hub。Script-Hub 仅作为语法处理参考。

返回封闭工具对象的匿名立即执行函数与命名工厂使用相同的状态和完成传播分析；包含 `this`、`arguments`、动态 eval 或逃逸接收者时不套用此规范化。HTTP 辅助函数可在 `return` 中选择已知客户端方法；空对象逐步构造请求时读取实时字段，条件正文和 Header 保持可选，新增 URL 必须支配请求。异步辅助函数的立即返回值被外层使用时继续拒绝，避免把原本忽略网络回调的等待改为串行网络等待。

定时脚本保留普通数值运算、数值格式化和封闭辅助函数返回的字符串；原型被改写或可能返回函数时继续拒绝源码字符串化。仅通过 `new` 调用且无构造函数反射的普通函数可保留实例 `this`；闭包在无条件初始化后创建时可使用已初始化的原隐式变量。多段 Promise 链保留原始 then/catch/finally 顺序，完成后跳过后续处理器。明确为 `false` 的 `throwHttpErrors` 对应原生 HTTP 返回错误状态响应的行为，网络错误继续走拒绝分支；其他取值暂不推测。

旧 Env 写法另参考 [AsVow/OpenAPI](https://github.com/asvow/openapi) 的 `API.js`（审阅版本 `3da8fc2c259380e4c6a41ace70a4f2a42e820329`）：环境探测、HTTP 默认参数合并、请求与响应钩子及超时竞争均属于需要分析的源程序行为，不能因其属于兼容封装而整段删除。该库仅用于理解输入契约，不作为构建或产物的运行依赖，也不表示任意版本的完整封装均已可转换。

Promise 完成链支持 `then(onFulfilled, onRejected)` 的两个可追溯回调，包括初始化后不可变的命名函数。第二个回调只处理接收者的拒绝；成功回调自身抛错由后续 `catch` 处理。原生完成返回会阻止后续回调和清理副作用；普通回调的返回值、拒绝及异步等待继续保留。未知 thenable、可变或无法解析的回调仍拒绝转换。

未等待的根 Promise 完成链只有在调用图可静态闭合时才保留原启动点并发运行：基座必须是立即执行的异步函数、标准 Promise 工厂，或全部引用均为直接调用且声明支配调用点的本地函数；完成回调必须是内联函数或初始化后未改绑、未逃逸的命名函数；启动点不能位于条件、循环或异常旁路；根之后只能有函数声明或另一个同样可证的完成根。绑定写入、提前调用、跨闭包逃逸、没有 Promise 契约以及混合普通后续执行继续拒绝，不以忽略分支或放宽回调目标换取转换成功。

Env 中被丢弃的逗号、条件及短路表达式可先展开为语句，再进入同一 HTTP 原生编译链；保留 Header 修改、条件和求值顺序，不改写赋值或参数中被使用的 HTTP 返回值，也不把后续并发工作改为串行。回调响应用于模板日志、JSON 序列化或可追溯的字段修改时，只生成 `status / statusCode / headers` 数据记录，正文仍由原始回调赋值；原生 Headers 的多值字段和 full-header-mode 分别按相应契约读取。未知响应字段及未知消费者继续拒绝。

已审阅的 OpenAPI HTTP 工厂还可按封闭调用点证明请求字段：保留字符串 URL 归一化、默认参数展开合并、实时 Header / 正文及原有超时竞争，仅将实际网络调用暴露给原生 API 编译器。工厂以忽略变量改名的 AST 摘要匹配，并证明所有客户端引用及传输开关；报告记录 `closed-http-factory-fields`、工厂摘要、字段和调用点数量。未知请求钩子、逃逸到外部修改器、动态字段或未审阅的工厂实现均不能使用该证明。工厂返回值的 Promise 契约由同一份静态证据传给完成链分析，不把任意名为 `get` 的方法当作 Promise。

同一脚本被不同作者的模块引用时，发现阶段合并全部入口类型，不允许后处理的作者仓库覆盖集合中的定时入口。构建在编译前再从实际模块声明确定入口集合，编译与差分验证使用相同上下文，避免把已裁剪为 Cookie 获取入口的产物用于定时任务。只有来源平台、二进制模式和参数契约均相同的转换输入共享入口集合；不同运行契约的产物仍分别编译与验证，不因 URL 相同而串用阶段。

跨作者自动发现的依赖不会作为原作者仓库的清单覆盖项；作者仓库随后发现其他平台模块时，按其实际平台重新生成依赖标识，避免一个变体覆盖另一个变体的来源平台。版本 2 清单只登记来源与抓取规则，不配置显式脚本或 `script_overrides`。

定时任务集合仍以整个模块为单位处理：所有依赖均通过转换后才生成集合，任一依赖失败则排除整个集合并报告原因，不拆成独立任务卡片，也不删除失败条目发布部分集合。上游启动异步任务后立即调用完成函数时，转换器不会擅自延长执行时间或改变完成顺序。

封闭 Env 工厂的环境判断从实际方法正文和静态平台分支推导，不凭 `isNode` 等方法名猜测结果。可追溯的构造参数、默认参数、HTTP 参数别名、可选正文和只读日志消费者进入同一原生编译链；接收者传给未知辅助类、方法被覆写或响应对象逃逸时仍报告具体缺口。参数传播和语法树索引在单次编译内复用，跨脚本、跨构建不复用转换结果；单份原文超时按失败依赖记录，不中止其他无关模块的构建。

封闭的 HTTP 方法别名与条件选择在构建时展开，保留选择表达式的求值时间和次数，再转换请求参数与回调；不能把旧客户端函数引用直接替换为参数契约不同的原生函数。嵌套响应转发从运行时实参读取数据，合并各调用点已证明的字段，并保留默认空对象的完成行为，不把调用处的局部表达式搬入转发函数。未知方法逃逸或存储中的完整请求对象仍需证明字段契约，不能以静态转换成功掩盖数据流缺口。

脚本自身的正文用法注释若只有指向该文件的 QX 声明，且 AST 证明只使用文本消息字段与 `$done`、存在可识别的字符串完成调用，构建会按该脚本的 QX 完成契约转换，即使引用它的是 Loon 模块。匹配的是原始脚本 URL，不按作者或仓库名猜平台。多平台声明、环境检测、存储 / HTTP / 参数等平台 API、二进制正文或不能证明的字段访问仍以配套模块平台为准。单独调用转换器时使用 `--format qx` 明确选择。语义依据：[Quantumult X 官方正文重写示例](https://github.com/crossutility/Quantumult-X/blob/master/sample-rewrite-with-script.js) 和 [Egern 返回值](https://egernapp.com/zh-CN/docs/javascript-api/#返回值)。

脚本格式的入口允许 `surge`、`loon`、`qx`、`stash`、`shadowrocket`、`egern`。这不表示任意平台的全部模块配置、运行时扩展 API 或未来语法都能等价转换。Clash classical 是行式规则 payload，不包含整个 Clash 配置或 JavaScript Script 运行时。

普通 JavaScript 接收者按 AST 证明后保留：未被改写的 `Object.create` 属性描述符中的 getter / setter 拥有对象接收者；无继承类的实例 `this.toString()`、字面量接收者及不可变局部变量经 `typeof` 分支证明为非函数时，不按函数源码自检拒绝。静态类接收者、未知继承、裸函数 `this`、函数接收者以及赋值、解构或循环重绑定后的类型假设仍不放行。这些证明只消除误拦，不替代平台 API 映射与完成结果传播的验证。

只转发两个原始参数的 HTTP 辅助函数在平台分支确定后自动展开；只允许无重赋值、无逃逸且不使用返回值的直接调用。Promise 执行器中的普通 HTTP 回调可保留原有 resolve / reject 逻辑，网络请求和正文读取直接调用 `ctx.http`；整体响应对象逃逸仍拒绝。完整响应可写入局部包装记录的 `response` 键，但仅当该记录只含静态字段、经封闭转发函数交给同一 Promise resolver，且所有 `response` 读取都只是真值观察或已投影的 `status / statusCode / headers`；读取正文、未知字段、建立别名或把记录交给未知函数仍拒绝。`catch/finally` 完成链按原顺序传播结果，末尾提升函数声明不作为额外执行任务。

源文件内关联的 jq / Mock 文件通过原作者仓库解析器读取，内容和校验信息进入依赖记录。跨仓库依赖自动从原始 GitHub raw 链接追溯仓库、固定提交、缓存原文并解析许可证，不需要逐项手填；依赖按实际作者 / 仓库存放和署名，页面来源仍归属配套模块发布者；原生 Egern 文件正文保持原样。未确认的 DNS 回调协议、动态代码执行和无法证明语义的 API 继续报告具体原因，不静默忽略。

Loon V2 的词法解析位于 `tools/egern_hub/loon_v2.py`，由现有 `convert_module()` 调用；它没有独立的转换命令或构建流程。来源模块与 README / 注释中的新版 Script 均由原有发现器识别，关联 JS 继续进入同一原生 API 编译器。URL 正则保留 i/m/s 标记、字符串与反引号原始字符串的区别，插件对象参数保留类型；文件引用仍通过统一依赖读取器追溯。参考 Loon 官方 [Script 转换器](https://nsloon.app/script-converter/) 与 [Rewrite 转换器](https://nsloon.app/rewrite-converter/) 及其新版语法文档，不调用这些在线服务执行转换。

经典 Loon 的 `cron`、`generic`、`network-changed` 与新版声明进入同一原生脚本链，分别输出 `schedule`、`generic`、`network`；动态 Cron 字符串和启停开关保留为模块参数。V2 迁移残留的裸 `enable` 只在已声明布尔参数时规范为变量引用；缺失声明仍由同一脚本原作者的配套模块补全，不猜默认值。单一 URL 条件有唯一结束分隔符且不含复合条件时，可以规范内部未转义的 `/`，不改变匹配语义。每次规范记录原始行和原因；损坏的替换字符串、缺少动作及含糊的条件继续拒绝，不能靠丢弃规则发布半个模块。

当前原生映射覆盖 URL 条件及其 AND / OR、固定字符串 URL、常见 Reject、响应 Mock、JSON 增删改 / jq / jq_file、正文正则、Header set / del / add 和单独的 URL 替换 / 重定向。Header add 由既有原生 Headers 编译器实现追加及多值保留。方法 / Header / 状态条件、动态超时与 debug、Header 正则替换、请求正文 Mock，以及需要跨不同原生配置阶段保持顺序的混合管道仍明确拒绝，不删除条件或丢弃动作来冒充成功。未知属性、重复参数、缺少引号、未闭合字符串 / 正则、裸参数名等错误逐行报告；原作者损坏的 V2 声明不会自动猜测修补或发布成残缺模块。

验证命令：`.venv/bin/python build.py --offline --verify`，单元测试 `.venv/bin/python -m unittest discover -s tests`。测试包含递归逻辑、引用边界、JSON 路径、参数类型、平台环境判定、二进制 Mock 和执行顺序；探针未触发行为不记为功能通过。

大型模块遇到多处错误时，构建报告的 `diagnostics` 一次列出全部异常声明及原始行号，整个模块仍拒绝发布。Loon 标签中的逗号和行尾逗号、未加引号的完整 jq 行尾可直接解析；不猜测未声明开关、损坏的 URL 或残缺的替换参数。

Loon 经典声明被放进错误配置段时，只对语法明确的完整 `http-request / http-response ... script-path=` 和 `URL reject...` 自动识别真实类型，逐行记录 `normalizations`，不改变后续声明所在的原始段。来源原文保持不变；不能可靠识别的声明仍列入错误。

原生编译前执行有界静态简化，不执行上游代码：只展开已初始化、未被修改、未逃逸且读取位置可证明的字面量表；只删除同一块中自由 `$done()` 调用后不可达的表达式，保留可能影响提升的声明。字符串表轮转位于逗号表达式时只移除轮转项，同一语句中的其他业务项及其求值顺序保持不变。闭合对象或数组字面量可在无写入、无动态键、初始化前缀无调用且嵌套函数只会在初始化后进入时折叠静态死分支；任何提前读取、写入或逃逸证据仍保留原分支。局部化循环中的隐式变量时，要求所有引用均在同一循环和函数内，初始化右侧没有提前读取，且不覆写宿主全局。仍在执行路径中的动态解码、自防御或源码检查不会因此放行。Env / MagicJS / 客户端契约使用忽略局部变量名称与格式的 AST 摘要，代码行为、外部绑定或引用方式改变时继续拒绝，不按脚本 URL 放行。完成入口必须追溯到本地已证明的提供者；未知全局构造出的实例即使以 `Env` / `MagicJS` 命名，或把完成调用包在条件与回调中，也不能据此认定存在平台完成路径。完成函数仅被 `typeof` 观察时属于只读存在性检查，不构成回调逃逸；同一函数被交给未知高阶函数或对象时仍拒绝。

要在声明错误尚未修复时继续审计所有显式脚本依赖，可运行：

```sh
.venv/bin/python -m tools.egern_hub.audit_module \
  https://github.com/fmz200/wool_scripts Loon/plugin/blockAds.plugin \
  --offline --output verification/local/blockads-audit.json
```

去掉 `--offline` 则刷新上游快照和依赖。默认只做声明检查与各二进制模式的原生 API 静态编译，输出原始行号、实际作者和具体错误；即使声明无效也继续扫描依赖。它不发布残缺模块，不替代参数契约、动态差分验证或真机测试；有异常时退出码为 1。报告留在忽略的 `verification/local/`。

`build.py --verify` 从模块规则与原脚本 AST 自动生成确定性探针，并对全部已编译依赖运行原文 / 原生脚本差分，通过 `included_in_site` 标明依赖是否进入站点。无法生成有效输入或未触发行为的分支继续标记为未覆盖，不算功能通过。审计命令只按实际声明的二进制模式运行，不伪造模块参数或 enable 默认值。

NSNanoCat/util 用于核对平台识别、存储、等待和网络选项差异；其 Egern 分支仍有旧式全局 API，不能直接作为本仓库的原生运行时。这里在构建时选择可证明的分支、展开封装，最终只生成原生 API 调用；没有引入该项目的包或运行依赖。官方未列出的字段 / 宿主能力保留为待确认项，不据此断言 Egern 一定不支持，也不编造 ctx 字段替代。

公共库保留在任何简化、平台识别、格式化之前识别，构建期间以声明占位保留对外绑定，转换完成后恢复原文，不从 CDN 下载替代版本、不增加运行依赖。text-encoding 的旧全局接收者用一次显式 `call(globalThis)` 保持；库正文仍逐字保留，该边界不模拟任何代理 API。应用专属 protobuf schema 仍作为普通 JavaScript 保留，`globalThis.Object` 等标准内建读取允许原样使用；全局代理对象访问仍拒绝。

脚本分发沿用上游 ASCII 路径和文件名，例如 `scripts/app2smile/rules/js/tieba-proto.js`，不追加构建 ID、平台或摘要。不同模块对同一原文的转换结果（含署名、原文说明）完全一致时共用一个文件；每个原平台 / 参数契约仍独立保留转换与差分验证记录。用法注释只列一个独立配套模块：该模块的全部脚本引用必须指向当前物理脚本文件；等价转换 ID 按最终分发路径合并判断。多个候选按配置长度、模块地址稳定排序，保留最精简的一份，不拼接集合的参数和 MITM 域名。没有独立模块时保留通用用法提示，不引用大集合。确有不同原生代码的契约使用 `variants/<平台>-<text|binary>[-object-argument][-enabled]/原文件名.js` 子目录区分，不覆盖另一版本；未知契约或不同原文占用同一路径时明确报错。构建从原文重新计算全部地址，并整体替换站点目录，旧平台 / 哈希命名文件与失效引用不会保留。网站按内容寻址的 JSON 数据文件及原文缓存摘要不属于资源分发文件名，继续保留缓存用途。

`tools/js-analysis/analysis/libraries.mjs` 登记的是完整代码的 AST 摘要和公共库源地址，不是作者脚本的发布状态。注释库名不能触发豁免；内容变化必须重新匹配，库的外部辅助函数也会沿词法依赖检查，不能借公共库隐藏 `$done` 等平台调用。`conversion.json` 与模块审计记录 `preserved_libraries`（库名、来源、范围和契约摘要），便于追溯；识别出公共库也不代表外围平台框架、动态参数或模块声明已完成转换。

独立函数声明形式的完整公共库也按完整 AST 契约识别，包括 js-base64 的 Base64Code 构造器；保留构造器正文与对外绑定，不改写内部 this、编解码或类型判断。函数重命名仍可识别，修改算法或混入平台 API 则不再匹配。

多声明 CommonJS 公共库前缀按完整 AST 契约识别，并在首个代理 API 语句前停止候选范围；不因出现 `exports` 或 CryptoJS 名称就放行。库范围的 start/end 为 JavaScript UTF-16 偏移。he / js-base64 的旧全局导出接收者与 text-encoding 一样显式绑定到 globalThis，库正文不改写。

旧 Env 实例的原型方法名可被业务作为自有数据字段使用：只有根层无条件赋值支配所有后续读取、类内没有该字段引用，且实例不逃逸时，才裁剪不可观察的原型方法。裁剪后重新执行实例展开，再按封闭调用点分析 HTTP 回调，避免残留 Env 回调参数被误判为未知函数。Http facade 的语句式 GET/POST 分支按完整 AST 契约识别，正常响应与传输失败均保留作者 Promise 的 resolve/reject 行为。

局部结果变量在 try/catch 中赋值、finally 中完成的脚本，会由语法自动选择结构化完成传播。所有赋值必须是可证明字段的普通对象，结果变量不得逃逸或传给未知函数；保持第一次完成结果，并阻止后续 finally 覆盖。该能力不依赖作者、文件名、库名或人工转换状态。

差分验证仍禁用 VM 动态代码生成；依赖 protobuf.js 动态生成编码器的输入可能因模拟宿主限制无法完成，报告会保留原侧错误，不把双方报错记为功能通过，也不因此去改写公共库。原文保留只证明转换器没有改动该库，不能代替其运行环境兼容性验证。

维护者提供的 Egern 导出是配置语法参考，不作为构建输入或人工修复清单。导出中的 `_compat.$argument` 与原始脚本地址不代表脚本已原生化；构建仍要求 AST 原生编译。样本中未引用 jq 的 `.data = []` 被截为 `.data`、部分错误声明被省略、损坏 URL 被原样保留，不能把这些有损结果当作自动修复依据。原生 YAML 中的裸 `=` 按字符串安全读取，不修改作者正文。

已审查的 jsjiami RC4 字符串表由 `tools/js-analysis/transforms/decoding.mjs` 静态解码。工具只展开字符串字面量、数组及单 return 的数组工厂，用独立 RC4 实现和有界常量算术校验表旋转，不执行上游解码函数。轮转调用若只是顶层逗号表达式的一项，只删除该项并保留兄弟业务表达式；轮转项之外的调用、成员写入和逃逸仍按原语句契约拒绝。解码器、旋转逻辑与完整解码后的自防御壳分别校验 AST 契约，壳契约包含业务区域的位置，避免业务挪至初始化之前仍被放行；契约不按文件名或来源 URL 放行。业务区域的声明、循环和赋值均从本次原文读取，源头修改后自动重新生成；未知壳、非常量调用、业务对壳变量或 console 状态的依赖仍拒绝转换。构建和审计报告通过 `static_transformations` 记录移除的调试器、定时器和日志屏蔽壳。

经典 Loon 声明仅对可机械辨识的粘贴错误做规范化：同阶段、两个完整引号值之间重复的正文阶段标记，以及误粘贴进匹配式且在尾部完整重复的 tag / enable 文本。`normalizations` 保留原始行号、原文、规范化结果和原因，不修改上游文件。未声明开关的默认值、不同阶段标记或无法确认的匹配式仍报错，不猜测启停行为。

新版 Loon 正文替换出现损坏引号时，构建只在同仓库、同目录中查找去掉 `V2` 后的经典配套模块。URL 匹配式、查找正则及损坏替换串必须与经典声明对应，且所有证据得到同一个替换值，才能恢复引号；审计记录依据文件地址和原始行号。没有配套证据、存在多义值或正则 flags 不匹配时继续拒绝，不按作者、模块名或人工修复表放行。

V2 脚本声明遗漏二进制模式或插件对象参数时，也只从上述经典配套模块中，按完全相同的触发阶段、URL 正则正文和规范化脚本地址恢复显式值。已有 V2 值不覆盖、不同匹配式不借用、冲突证据拒绝；恢复后的对象参数继续使用当前模块的参数声明及用户值，不能固定成经典版默认值。报告逐项记录 `restored` 和依据行号，避免二进制 Protobuf 被误当文本，或脚本功能开关在迁移中丢失。

纯拦截模块的裸 HTTP 匹配式可按一致策略补全：至少两条显式分流规则全部为 `REJECT`，且显式重写全部是 reject 动作，才将缺动作的裸 HTTP 正则补为拦截规则。这是依据模块统一策略的推断修复，`normalizations` 明确记录原文、补全结果及推断依据；混合 DIRECT / PROXY、重定向和未知声明不会参与推断。定时列表中 Cron 表达式后的唯一 HTTPS 地址可自动补上 `script-path` 字段名。

依赖地址已删除时，解析器只在原作者的同一仓库与 ref 中，按末级应用目录和原文件名查找唯一新路径；有多个候选或仓库不可用时仍报错。报告写入 `dependency_relocated`、旧 / 新地址及引用模块，生成脚本按新路径和来源署名；不从其他集合库兜底。整个过程复用固定快照、缓存和离线构建。

JavaScript 原生编译支持封闭的回调转发函数、响应别名 getter、部分分支调用完成函数，以及函数内含说明注释的异步 IIFE。转换仍保留普通 JavaScript 的闭包、参数求值顺序、错误与结果传播，最终只调用 Egern `ctx` API。数字或可追溯的标准字符串 / 数组 `toString` 不当作动态源码检查；修改相关方法或无法证明接收者类型时继续拒绝。

构造函数中赋给实例的方法，可从全部封闭调用点推断字符串参数，用于直接生成原生通知 URL；同时检查实例未逃逸、方法未被替换、构造函数未返回其他对象、`arguments` 未修改参数。由已初始化根声明捕获的字符串也可沿回调创建点追溯。共享 HTTP 配置的 URL / 正文若始终由字符串覆盖，原生请求读取调用当时的字段，不重放旧初始化值；未知类型或传输选项修改仍需单独证明。

通知选项的 `typeof` 字符串分支与空值分支可按控制流追踪；局部选项变量仅在全部写入均为已证明的字符串 / 空值，或封闭调用传入的普通默认对象缺少对应属性时直接生成原生通知操作。参数修改、访问器、原型修改及未知对象不按缺失属性处理。函数内声明之后创建的回调可读取已初始化的字符串，提前创建或无法证明调用时机的闭包仍拒绝。

单个根异步完成任务后跟随普通同步循环或字符串处理时，编译器保留任务启动位置，在同步尾部之后才等待结果；同步分支已经完成时直接返回，不执行尾部。仅允许可追溯的同步辅助函数、标准数值 / 字符串操作和日志；未知调用、额外异步工作、访问器及不能确认的属性读取继续报告，不通过提前 await 将原并发串行化。

回调委托只在原有映射无法完成静态证明时展开，再对展开结果执行完整的原生证明；已有可证明的调用结构保持原有转换路径。多个嵌套委托逐个展开、逐次重建作用域，避免外层回调遮蔽内层替换。持久化写入先按原顺序、各一次求值数据和键，运行时空值删除映射到原生 `storage.delete`，不把转发参数中的 null 存成普通值。

`eval(method)` 保持 JavaScript 原生调用。有限函数名称表可以辅助绑定和调用范围分析，但主转换流程不再生成替代分发表，不注入求值兼容函数。`Function`、存储表达式求值及普通 `toString()` 遵循同一规则；动态文本的 API 分析限制见 [转换边界](conversion-boundaries.md)。

旧脚本在非严格模式下条件创建的隐式全局，转换为入口内的局部变量与初始化标志；赋值右侧只求值一次，未赋值读取继续抛出 ReferenceError，typeof 保持 undefined 语义。严格模式赋值、delete 及无法证明完成传播的条件函数调用仍拒绝，不把未创建的变量静默变成 undefined。

同步尾部的运算、模板插值、计算属性与标准方法参数必须证明为标量，避免对象的 valueOf / toString 隐式发起额外任务；涉及原型或标准方法修改时不假定内建语义。

另审阅 [Peng-YM/ScriptConverter 的早期 js-converter.js](https://raw.githubusercontent.com/Peng-YM/ScriptConverter/refs/heads/master/js-converter.js)：其通过向源码注入 $httpClient / $task、存储和通知兼容对象实现跨平台执行，并按两类 API 是否同时出现来跳过多平台脚本。本项目只将该实现用于核对基础调用差异，不引入其运行时包装，也不以 API 名称共存作为原生兼容证明。

默认对象的缺失字段推断同时检查 Object / Reflect 原型反射与构造器逃逸；不能证明原型稳定时，保留实际属性读取，不将继承属性折叠为 undefined。普通继承数据继续原样执行；用于原生通知选项时仍须建立字段契约。

封闭同步 helper 返回新解析的 JSON 或布尔失败标记时，可沿不可变绑定推断普通数据字段，保留字段的标准 `toString()`。推断要求 JSON 在创建函数内未修改、未传给未知调用，调用结果也未修改或逃逸；继承的 `constructor`、`toString`、数组方法等字段不视为 JSON 数据，避免漏过函数源码自检。

根 Promise 完成链启动后安装 `Date.prototype` 格式化方法时，结构化转换保留启动点，在同步安装后才汇合完成结果。仅接受一个可追溯的根完成链、函数声明及直接的方法函数赋值；原型别名、反射修改、特殊成员和未知尾部操作不参与该推断。同步完成仍立即返回；无花括号的 if / else 分支保持归属。

该命令只输出本地诊断，不生成站点或拆分发布。依赖问题未收敛时不反复运行全站构建；集合的依赖转换及差分验证通过后，再统一全量重转历史脚本、校验并更新预览。期间预览保留最近一次通过验证的产物。

结构化根 Promise 的延后汇合也支持后续的无副作用标量声明，保留启动前后观察到的变量值；仍不接受未知调用或对象初始化。逗号表达式的最后一项若为完成调用，可按尾部调用传播异步结果，前面的表达式维持求值顺序；后面仍有其他表达式时继续拒绝，避免改变并发顺序。

通过 `globalThis.$argument`、`globalThis["$done"]` 等静态只读成员读取已选平台 API 时，转换器先做词法绑定和全局对象逃逸检查，再交由既有原生映射处理。局部同名对象保持普通 JavaScript 语义；全局对象写入、传给未知函数和有冲突绑定的访问继续拒绝。

完整内嵌 CryptoJS 包按精确 AST 契约原样保留，包括其全局导出接收者；已审查的加密、散列返回值契约交由 `tools/js-analysis/analysis/values.mjs` 做封闭命名空间与别名证明，避免将密文对象的 `toString()` 误判为函数源码自检。命名空间被写入、遮蔽、传给未知函数或调用未知成员时，不获得该证明；库内容变化后须重新审查。

局部变量先来自未知数据、随后在同一语句块明确赋成数字或字符串时，值推断按支配当前读取点的赋值继续分析；闭包捕获、直接 eval、分支写入或同一表达式里的中途改写会使该证明失效。

当可追溯的完成回调由循环或同一语句块中的多个调用并发启动时，结构化转换保留启动点，以标准 JavaScript Promise 汇合原生结果。每个请求直接调用 `ctx.http`，没有旧平台 API 对象、轮询或异常哨兵；首次完成后抑制其他完成回调的副作用，异步异常传播为原生入口拒绝。只用于返回值未被消费的明确语句调用，未知回调或 Promise 契约仍拒绝。

可追溯的标准 `Promise` 同步执行器及其封闭同步 HTTP 转发函数可以包含完成回调。转换保留执行器同步启动与参数构造异常的拒绝路径，HTTP 仍直接调用 `ctx.http`；原生入口以标准 Promise 结果汇合，等待可能因提前完成而不再 resolve 的原业务 Promise 时使用 `Promise.race`，不把执行器改成 `async`。不能证明的执行器、构造器修改／逃逸仍拒绝。已知一次性 `setTimeout` 完成回调保留原延时和递归轮询，只编译其中的完成传播；不改写普通定时语法或补造设备 API。完成出口识别覆盖 `then`、`catch`、`finally`，非完成的可证明 Promise 链保留其忽略返回值和原启动位置。

旧 Env 工厂返回封闭普通对象时，调用者后续追加的静态数据字段可按绑定身份替换成独立局部状态；初值仍为 `undefined`，更新表达式、字段名与工厂内部同名变量的区别、非函数初始化副作用保持不变。方法覆写／逃逸、动态字段、删除字段、继承字段以及可观察 `Object.prototype` 或 eval 的对象不获得这项证明。工厂局部值的生成声明为初始化表达式加括号，保留逗号表达式的语法边界和求值顺序。此变更仅解决 Env 展开，不将剩余未知 HTTP 选项视为可发布。

共享请求对象中的 `opts.filter` 按实际调用 API 区分：它是 Quantumult X 的独立响应过滤器（官方示例：<https://raw.githubusercontent.com/crossutility/Quantumult-X/master/sample-fetch-opts-filter.js>），不会在 Surge / Loon 等回调 HTTP 分支执行。该分支仅允许可追溯、无修改和逃逸的静态字符串过滤选项，不把字符串当作可执行源码，不将其传入 `ctx.http`；未知字段、访问器、动态初始化仍拒绝。QX 分支仍须证明其响应过滤语义，不可使用此规则静默忽略。

封闭请求记录可保留 `console.log/info/warn/error/debug` 的普通打印，前提是全局 console 只通过这些成员直接调用、没有覆写或逃逸；未知观察函数仍不获得只读证明。条件表达式两侧的普通请求对象合并字段集合，URL 必须始终存在，缺省正文／请求头按实际存在性投影，传输标志仍要求各分支相同。空对象在 `if/else` 两侧赋 URL 时，按控制流证明调用前必定赋值，不执行条件、不重放初始化或覆盖表达式；循环或单侧赋值不能替代该证明。
