# 模块自动判定流程

`build.py` 在本地、GitHub Actions、Cloudflare Pages 中执行同一套确定性流程。以 `catalog/ios151--rewrite.json` 为例，只维护仓库、分支、许可与显示元信息，不维护哪些脚本已经转换的人工白名单。

1. 读取原作者仓库目录和对应提交的原文，包括配套配置、README、JS / MJS。
2. 验证原生 Egern YAML；同一项目已有原生模块时优先使用，保留原文、注释、作者和脚本 URL，不转换其脚本。
3. 没有原生模块时，优先转换 Surge / Loon / QX 配套配置，自动解析全部依赖，统一转为 Egern 原生模块与 ctx 脚本。
4. 没有可用配套模块时，解析脚本开头多段注释与 README 配置代码块，依据明确的脚本 URL、请求 / 响应阶段、匹配规则与参数创建模块。支持带配置段或独立的标准脚本声明，不从业务代码猜测安装方式。
5. 缺少用法、无法确定关联关系、存在转载限制、依赖缺失或转换器不支持时跳过，记录原因。任一依赖转换失败则跳过整个模块；不发布残缺模块或独立脚本卡片。
6. 每次全量重转当前模块依赖，通过语法检查后整体替换站点，自动清理失去引用的脚本与旧模块。

同项目按原始路径、平台目录和平台后缀匹配；同一配置的多平台版本按 Egern、Surge、Loon、QX 顺序选择。原生模块中的外部依赖原样保留；转换模块不得悄悄替换仓库外作者的脚本，需另外登记其出处。

README 与注释中的纯自然语言、没有明确安装参数的功能介绍不视为可执行配置。未知 API、动态代码与复杂混淆不会被声称转换成功。源文件不被执行；批量 Acorn 分析与语法检查均在构建时完成。效果仍需 Egern 与目标 App 真机验证。

模块命名同样由构建完成：先取配套配置的声明名，同项目其他平台配套模块的名称也优先于脚本注释；没有时读取脚本开头注释的名称、tag 或 UA，解码 URL 编码。编号、安装步骤等不作为名称。仍缺名时，联网读取 MITM 域名首页的站点元信息或标题，过滤验证页、默认服务器页与错误页。结果缓存于本地 `data/site-names.json`，24 小时内复用；离线构建只读缓存。无有效标题时保留文件名。转换 YAML 与页面使用相同名称；原生 Egern 文件原文不变，公开文件路径也不变。

卡片说明也由构建从原文提取，忽略清单中的手工 `description`。按上游模块的声明说明、模块 / 脚本注释、相关 README 的顺序选择；自动解码 URL 编码，过滤作者、日期、代码和配置。README 通过原始文件链接、同名章节或脚本专属目录关联；表格只取对应行，不混用其他模块章节或整个仓库的简介。

缺少源头说明时，通过 Acorn 批量解析原始脚本，追踪完成入口输出、JSON 对象与别名修改、文本替换、数组处理及可识别的 API 调用，结合模块规则生成行为概述，分析来源保留在构建报告中。固定字段规则可以描述会员状态、订阅回执、到期时间等数据类别，不推断实际解锁效果。未关联输出的常量、注释、局部同名 API 和未调用函数不作为行为依据；动态执行、未知函数和追踪深度限制记录于报告。无法判断具体变更时描述配置中的脚本触发阶段及分析限制。整个过程不执行作者脚本，也不调用 AI。源头说明变化或删除后，下次构建重新判断。转换模块的说明随之更新，原生 Egern 文件逐字保留。

`dist/build-report.json` 的 `decisions` 记录路径、来源仓库、快照提交、判定和原因；`script_errors` 记录具体转换错误；`names` 记录模块最终名称、依据（module / comment / website / filename）、出处 URL 及网站查询失败原因；`descriptions` 记录说明与依据（module / comment / readme / behavior），行为分析项包含 `scripts`（URL、操作、字段、原文行号及限制）、`configuration`（配置统计）、`limited`（是否仅能描述触发阶段）和 `upstream`（源头说明缺失原因）。`dist/conversion.json` 只登记实际发布模块所需的脚本及其校验值。页面只加载可用模块与规则，不展示来源脚本、待适配条目或构建诊断。

原始仓库索引保存在对应 `sources/作者/仓库/分支/.hub-index.json`，与原文、产物一起忽略，不提交 Git。`repository_import` 只将本地原作者检出导入相同缓存，不生成已转换清单。删除注释用法或配套配置后重新构建，相应模块会自动退出目录。
