# 剩余 54 个失败脚本的 ROI 排序（第二十轮）

## 口径

- 基线：`55/109 URL`、`164/327 组合`；失败明细见
  `/root/egern/.local/round20-failures.tsv`，共 54 个 URL。
- 排序目标：按“补齐某项缺失能力后，能直接变成 E2E 成功的脚本数”排序；
  首阻塞脚本数不等于可解锁数。
- 保守计数：只有已经过静态证明、双向回归或 E2E 实验确认的解锁才计入；
  仅把首阻塞推进到下一层的能力计 0，不写成收益。
- 难度沿用 `.wrap` 判定标准：缺什么就写缺什么，不用“可能可以”补边。
- “直接解锁”指只补齐该项能力、不依赖其他缺失能力即可达到 E2E 成功；若仍需
  另一个独立证明层，按 0 计，并在备注中给出推进后的新阻塞。

## 1. 混淆字符串表原始访问器族

### 涉及脚本

| 源文件 | URL 末段 | 首阻塞原文（qx / surge / loon 相同） |
| --- | --- | --- |
| `1b374aabcab2d747.js` | `ChinaMobile/NoAds.js` | `混淆字符串表静态解析：js-obfuscator 轮转校验在一轮内没有匹配` |
| `132c32aec3c6a0b6.js` | `ChatGPTPlusCrack.js` | `混淆字符串表静态解析：js-obfuscator 轮转校验在一轮内没有匹配` |

### 证据与结论

- 两脚本都属于闭合字符串表族：表工厂是静态数组工厂，解码器有固定偏移，
  轮转校验和可由 AST 常量唯一复算。`ChatGPTPlusCrack` 的唯一轮转步数为 20，
  `parseInt` 校验和精确匹配；`NoAds` 的同表工厂同时包含 RC4 解码器与只读
  原始访问器，校验和必须按被调函数身份选择 Base64/RC4 或原始表读取。
- 现有实现把 `ks` 族的一参调用统一当成 Base64 解码，无法表达“只读原始访问器”
  这一角色；这既让 `ChatGPTPlusCrack` 的校验和失配，也让 `NoAds` 的混合族
  无法求值。补齐该角色属于同一个静态契约，不需要运行时猜测。
- 本轮实验：`ChatGPTPlusCrack` 在 `qx`、`surge`、`loon` 均为 `errors=[]`，
  产生 69 次字面量替换、`rotation_steps=20`；`NoAds` 三格式均推进到
  `Node/浏览器全局缺失探测结果传入了未知代码，无法证明可折叠：window`，
  没有 E2E 成功。

### 保守计数

- 直接解锁：`ChatGPTPlusCrack` 1 个 URL（3 个组合）。
- 上界 2：只有同时补齐运行环境全局族，`NoAds` 才可能继续；该部分不计入本项。
- 难度：中低。闭合 AST、唯一轮转、原始访问器纯读取均可静态证明；不需要
  放宽自防御壳或平台探测。

## 2. `.wrap` 状态机剩余边

### 涉及脚本（16 个首阻塞）

`kanlixiang`、`kugouv5`、`mdsq2`、`ins`、`insav.tv`、`haijiaoshequ`、
`pear`、`RRSP`、`LectMate`、`xv`、`ydm`、`mxy`（ios151）、`wpyx`、
`yangtao`、`mxy`（Yu9191）、`jvid`。

首阻塞原文分为三类：

- `结构化原生转换第 N 行：内联完成函数传给未知回调`（13 个）；
- `结构化原生转换第 4 行：完成函数传给未知回调，无法短路调用者`（`kanlixiang`）；
- `原生转换第 43 行：完成函数引用逃逸，无法证明返回值传播`（`LectMate`）。

### 证据与结论

- `docs/completion-state-machine-proof.md` 第十九轮：13 个目标源、42 台机器，
  仅 10/42 台可证；只有 `kugouv5` 的全部机器可证（1/13）。其余脚本缺：
  异常/finally 处理点入边、封闭辅助函数上下文映射、动态 `next`/`case`、
  generator 外部驱动、未被证明的 `finally` 副作用、保存槽、恰好一次和结果吸收。
- 第十一轮已复核“内联完成函数的结果无关性”：9 个被拦截函数都是 `.wrap(...)`
  正文，目标会读取返回值推进状态；临时全部放行后，9 个 URL 均只推进到新的
  HTTP/异步/求值顺序阻塞，没有 E2E 成功。
- 第十四轮对 `ins.js` 和两个 `mxy.js` 增加完整响应包装记录后，首阻塞仍回到
  `内联完成函数传给未知回调`；说明响应层不是唯一缺口。

### 保守计数

- 直接解锁：1（`kugouv5`），且只在完整补齐状态机所有不变量后成立。
- 单补一类边（例如只补异常边或只补动态 `next`）预计仍为 0，因为矩阵中其余
  脚本都同时缺多项；不能按“首阻塞是 `.wrap`”就乐观计 16。
- 难度：极高。该族需要完整的 CFG、保存槽、恰好一次、结果吸收、异常/`finally`
  和并发竞速证明；不是单单元可以完成的能力。

### 证据与结论

- `$done` 三件套（`KDF/m3u`、`plpl`、`lsp/plpl`）把 `$done` 作为值传给压缩 helper。

  再绕过该层后又变成 `转换结果残留平台 API：$done`。至少还缺 completion

  `通知参数 被传给未知函数，无法证明对象身份不逃逸`；两个通知接收者都是条件选择。
- `haijiao`：通知对象整体传递、动态 `$notification.[...]`、动态 `$task.[...]`
  和 `window` 同时存在，不能用一个“动态成员键”规则统一放行。
- `KDF/video-parser`：`$prefs` 整体传递，后续仍需要 HTTP/通知对象证明。

- 直接解锁：0。7 个脚本的根因不统一，且每个在单层放行后都有独立下游阻塞；

- 难度：高。需要按 API 分别建立整体对象快照、动态键白名单、字段级数据流和

## 6. `$environment.params`

### 涉及脚本（6 个首阻塞）

`ChatGPT.js`、`MediaCheck/check.js`、`Net_Speedlite.js`、
`generic_example.js`、`LocationDetection.js`、`NodeUnlockDetection.js`。

首阻塞原文：`未适配 API 成员：$environment.params`。

### 证据与结论

- `docs/environment-params-availability.md` 的正式结论：工作区内没有 Egern
  官方类型、官方文档副本或原生脚本证据能证明动态节点/当前策略/规则上下文参数；
  不映射到 `ctx.env`、`ctx.device`、`ctx.network` 或请求 `policy`。
- 该能力归入“既定策略拒绝”。即使猜测映射，也只能越过名称检查，无法证明节点名、
  地址、端口、TLS 和类型数据真实存在；继续推进仍会落入 HTTP 和完成流证明。
- 重开条件：取得官方 API 字段、官方类型定义或可复核的 Egern 原生运行证据。

### 保守计数

- 直接解锁：0。脚本数量最多不等于可解锁数最多。
- 难度：当前不可证；不是工程实现难度问题，而是缺少证据来源。

## 7. 平台动作标记契约

### 涉及脚本与事实

- `TOPlt.js`（`d2f1ac3a005da02f.js`）不在 54 个失败 URL 中：
  `round18-unit2-e2e.json` 显示 `qx`、`surge`、`loon` 三格式均为
  `errors=[]`、`ok=true`。
- 生成代码保留了 Surge 风格 `Env.msg()`，其中解构
  `$open`、`$copy`、`$media`、`$mediaMime`；`isSurge()` 被折叠为 true 后，
  代码选择 `$copy` 分支。这是已成功脚本的行为一致性债务，不是失败脚本的首阻塞。
- 全量源码中含 `$copy`/`$open`/`mediaMime` 的源文件共 7 个：3 个已成功
  （`TOPlt`、两版 `jd_price`），4 个仍失败（`ximalaya`、`KDF/m3u`、`pear`、
  `insav.tv`），但这 4 个的首阻塞都在平台动作标记之外的族。
- 对 54 个失败 URL 的直接解锁数：**0**。把 `isSurge` 折叠改成按原文平台选择，
  不会让任何一个当前失败脚本越过其首阻塞。

### 结论

- 排名低于所有能产生 E2E 增量的能力；可以作为独立的“行为一致性”正确性债务，
  但不能作为本轮 ROI 第一项。
- 若后续实施，必须保留既有平台探测折叠：只新增“原文平台动作标记选择”契约，
  不能为了让 `$copy`/`$open` 一致而改坏通用 `isSurge` 折叠。

## 本轮选择

按上述保守排序，本轮选择第 1 项：**混淆字符串表原始访问器族**。它已经有可复算的
静态证明和实测三格式转换结果，且单元边界可以落在“原始表访问器 + 同表工厂角色”
这一个契约内；不触碰平台探测折叠、`.wrap` 放行或任何脚本特例。
